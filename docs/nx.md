# Nx(ver 19~20) 종합 보고서

## 1. 개요 (Introduction)

### 1.1 Nx란 무엇인가?

Nx는 대규모 모노레포(Monorepo)를 효율적으로 관리하기 위해 고안된 오픈소스 도구입니다.
• Angular CLI를 확장한 형태로 출발했지만, 현재는 React, Node.js, Vue, Nest.js 등 다양한 스택을 지원하는 범용 모노레포 솔루션으로 발전했습니다.
• “Smart, Fast and Extensible Build System for Monorepos”를 슬로건으로 내세우며, 코드 재사용과 일관된 코드 스타일, 자동화된 빌드/테스트 파이프라인을 제공하는 것이 특징입니다.

### 1.2 문서 작성 목적

본 보고서는 Nx 19~20 버전대를 중심으로, Nx가 제공하는 주요 기능과 장점을 파악하고, 모노레포 환경에서 어떻게 활용할 수 있는지를 깊이 있게 설명하기 위해 작성되었습니다.
특히, Nx 19~20 사이에서 새롭게 추가되거나 개선된 사항(캐싱 전략, Nx Console, 플러그인 업데이트 등)을 소개하며, 기존 monorepo 툴(예: Lerna, Turborepo, Yarn Berry Workspace 등)과의 차이도 언급합니다.

## 2. Nx의 핵심 특징

### 2.1 모노레포 구조 관리

• 여러 프로젝트(프론트엔드, 백엔드, 라이브러리 등)를 ‘apps’ 및 ‘libs’ 폴더로 명확히 구분하여 한 리포지토리에서 관리할 수 있도록 돕습니다.
• Nx.json, Project.json, Workspace.json 등을 통해 프로젝트 의존 관계를 시각화하고, 특정 프로젝트만 빌드하거나 테스트하는 등 세분화된 작업이 가능합니다.

### 2.2 캐싱 및 그래프 기반의 빌드 최적화

• Nx는 프로젝트 간 의존성을 분석하여, 변경된 부분만 빌드·테스트하는 효율적인 작업 방식을 제공합니다.
• 빌드·테스트 결과를 캐싱(Cache)에 저장해놓고, 이후 동일한 입력이 재사용될 경우 캐싱된 결과를 사용해 불필요한 재빌드를 방지합니다.
• Nx 19 이후로는 “Distributed Caching”(원격 캐시)도 한층 강화되어, CI 환경 등에서도 캐싱 효과를 극대화할 수 있습니다.

### 2.3 멀티프레임워크 지원

• Angular 기반으로 시작했으나, 현재 React, Next.js, Vue, Nest.js, Node.js, Electron 등 다양한 스택에 대한 플러그인을 제공합니다.
• 각 프레임워크별 “Nx Plugin”을 통해, 생성(Scaffold), 빌드, 린트, 테스트, e2e 테스트, 스토리북, 배포 절차 등을 자동화하거나 단일 CLI 명령어로 처리할 수 있습니다.

### 2.4 CLI와 Nx Console

• Nx CLI(nx 명령어)를 사용하면, 프로젝트 생성, 의존성 그래프 시각화, 특정 앱 빌드/테스트 등을 간단히 수행할 수 있습니다.
• Nx Console(Visual Studio Code 등의 에디터 확장)은 GUI 형태로 Nx 작업을 도와주어, 명령어 옵션을 일일이 외우지 않아도 쉽게 프로젝트를 생성·관리할 수 있게 해줍니다.
• Nx 19~20 사이에서 Nx Console의 UI가 개선되어, 여러 빌드 옵션이 더 명확하고 직관적으로 노출됩니다.

### 2.5 스캐폴딩(Scaffolding) 및 코드 생성기

• “nx g @nx/[플러그인]:[스키마] [옵션]” 형태로, 컴포넌트/서비스/라이브러리 생성을 자동화할 수 있습니다.
• Angular/React/Vue 등 프레임워크별 코드 템플릿이 제공되어, 프로젝트 구조를 통일하고 생산성을 높입니다.

### 2.6 E2E 테스트 및 Storybook 통합

• e2e 테스트(예: Cypress, Playwright)를 Nx CLI로 실행·관리할 수 있고, 프로젝트 단위로 구분해 CI 파이프라인에서 병렬화가 용이합니다.
• Storybook과도 통합되어, “nx run <project>:storybook” 형태로 UI 컴포넌트 카탈로그를 손쉽게 관리·배포할 수 있습니다.

## 3. Nx 19~20 구간의 주요 변화

Nx는 버전이 올라갈 때마다 여러 기능이 추가되거나 개선됩니다. 여기서는 버전 19~20 전후로 달라진 핵심 포인트를 정리합니다.

### 3.1 캐싱 및 원격 캐시(Distributed Caching) 강화

• Nx 19 이후 분산 캐시에 대한 설정이 더 쉬워지고, 공식 Nx Cloud나 자체 호스팅 캐시 서버를 활용하여 빌드 결과를 공유하는 방식이 개선되었습니다.
• CI 파이프라인에서 변경된 프로젝트만 빌드 및 테스트받도록 하는 전략이 더욱 강력해졌습니다.

### 3.2 플러그인 업데이트 및 생태계 확장

• React, Angular, Nest.js 등 주요 Nx 플러그인들이 꾸준히 개선되어, 최신 프레임워크 버전을 바로바로 지원하거나 사용자 편의를 위한 Generator(스캐폴딩 템플릿) 기능이 대거 보강되었습니다.
• “@nx/next”, “@nx/eslint”, “@nx/web” 등 다양한 플러그인들이 추가·개선되어, 팀 내복잡한 설정을 단일 CLI에서 쉽게 처리 가능합니다.

### 3.3 Nx Console UX 개선

• Nx Console(VSCode 확장)에서 프로젝트·라이브러리 생성, 설정 변경 등을 GUI로 수행할 수 있고, 버전 20 전후에서 UI/UX가 한층 더 직관적으로 업데이트 되었습니다.
• 명령어 옵션별로 툴팁이 추가되거나, 에러 발생 시 힌트를 제공하는 등의 편의 기능이 강화되었습니다.

### 3.4 린트 및 포맷 통합

• “nx format”, “nx lint”같은 명령을 통해 모노레포 전역에서 공통의 코딩 규칙과 코드 포맷팅 규칙을 유지 가능하도록 개선되었습니다.
• 버전 20~21 구간에서 ESLint 설정이 더 단순화되는 흐름이 있으며, Nx로 린트/포맷 과정을 자동화하기가 더욱 수월해졌습니다.

## 4. Nx 사용 예시

### 4.1 초기 세팅

• 전역 설치 (필optional): “npm install -g nx”
• 혹은 로컬에서: “npm install --save-dev nx @nrwl/cli @nrwl/workspace”
• “npx nx new myworkspace --preset=react” 형태로, React 기반 Nx Workspace를 자동 생성할 수 있습니다.

### 4.2 프로젝트 구조

일반적으로 Nx Workspace는 아래와 비슷한 구조를 가집니다:

```
myworkspace/
 ┣ apps/
 ┃ ┣ my-app/
 ┃ ┣ my-app-e2e/
 ┣ libs/
 ┃ ┣ shared-ui/
 ┃ ┣ utils/
 ┣ tools/
 ┣ nx.json
 ┣ package.json
 ┣ tsconfig.base.json
 ┣ workspace.json (또는 project.json)
```

- apps/: 실제 실행 가능한 애플리케이션(프론트엔드·백엔드)
- libs/: 여러 앱에서 공유할 라이브러리(공통 UI, 유틸 함수 등)
- nx.json: Nx 특유의 설정 파일 (캐싱, 태그 규칙, plugin 설정 등이 포함)
- workspace.json(혹은 project.json): 각 프로젝트(app, lib)별 스크립트 정의, 빌드 옵션, 린트·테스트 옵션 등을 담은 핵심 설정

### 4.3 빌드와 테스트, 린트 예시

```bash
# 특정 앱만 빌드
npx nx build my-app

# 변경된 부분만 재빌드
npx nx affected:build --base=main

# 특정 라이브러리에 대한 테스트
npx nx test shared-ui

# 변경된 프로젝트만 테스트
npx nx affected:test --head=HEAD~1

# 린트
npx nx lint my-app
```

위와 같이 Nx CLI 명령어를 활용하면, 프로젝트 단위로 빌드/테스트를 구분해 효율적인 CI 파이프라인을 구성할 수 있습니다.

## 5. 다른 모노레포 툴과의 비교

### 5.1 Nx vs Lerna

• Lerna는 초기 가장 인기 있던 JS 모노레포 툴로, 버전 관리/퍼블리싱에 집중한 도구였습니다.
• Nx는 프로젝트 간 의존성 그래프를 분석하고 캐싱을 통해 빌드 시간을 단축하는 기능에 강점이 있습니다.
• Lerna도 Nx와 통합해서 쓸 수 있게 되었지만, 단독으로는 빌드/테스트 최적화 측면에서 한계가 있습니다.

### 5.2 Nx vs Turborepo

• Turborepo 역시 캐싱과 병렬화를 지원해 빌드 시간을 줄이는 목적을 지닌 모노레포 도구입니다.
• Nx는 “프로젝트 간 의존성 그래프”를 자동으로 계산하고 UI(Nx Console) 지원이 강력합니다.
• Turborepo는 설정 파일(turbo.json)이 상대적으로 단순하지만, 프레임워크별 코드 생성 등 Nx가 제공하는 플러그인 생태계는 아직 미지원입니다.

### 5.3 Nx vs Yarn Berry / pnpm workspaces

• Yarn Berry나 pnpm workspaces는 의존성 관리와 workspace 기반 모듈 설치를 쉽게 해주지만, Nx처럼 빌드/테스트 자동화 및 의존성 그래프 시각화 기능은 없습니다.
• 일반적으로 Nx Workspace 내부에서 npm, Yarn, pnpm 등에 대한 선택을 자유롭게 할 수 있으며, Nx 자체의 빌드 최적화 기능은 별도로 동작합니다.

## 6. 도입 시 고려사항

### 6.1 모놀리식 or 다중 레포 구조 분석

• Nx 도입 전, 얼마나 많은 프로젝트가 상호 연관이 있는지, 공통 라이브러리가 어느 정도인지 파악해야 합니다.
• 너무 단순한 앱만을 가진 조직에서는 Nx 도입 이점이 적을 수 있고, 오히려 설정이 복잡해질 수 있습니다.

### 6.2 팀 규모와 프레임워크 다양성

• Nx는 Angular, React, Vue, Nest.js 등을 혼합해 사용하는 대규모 팀에 이상적입니다.
• 여러 프레임워크를 한 리포지토리에서 관리하고, 코드 재사용과 공통 규칙 적용이 필요하다면 Nx가 적합합니다.

### 6.3 CI/CD 파이프라인 설계

• Nx가 제공하는 “affected:*” 기능을 활용해, 변경된 프로젝트만 빌드·테스트하도록 구성하면 CI 시간을 크게 단축할 수 있습니다.
• Nx Cloud나 자체 원격 캐시 서버를 운영해, 파이프라인 사이에 빌드 결과를 공유할 수 있습니다(버전 19~20 이후 더욱 안정화).

### 6.4 캐싱 전략

• Nx의 로컬 캐시(기본)와 분산 캐시(Nx Cloud, S3 등) 설정을 적절히 활용해야 합니다.
• 대규모 프로젝트에서 team A와 team B가 서로 겹치지 않는 코드만 변경했다면, 캐싱 덕분에 공통 부분을 다시 빌드하지 않아도 됩니다.

## 7. 결론 및 전망

Nx는 모노레포 환경에서 효율적이고 체계적인 개발·배포 프로세스를 구축하도록 돕는 대표적인 솔루션입니다.
• Nx 19~20 버전대에 이르러 분산 캐싱 기능, 플러그인 생태계, Nx Console UI 등이 더욱 발전하여, 대규모 조직에서 안정적으로 사용하기에 충분히 성숙해졌습니다.
• 기존 Lerna, Turborepo, Yarn Workspace 등과 비교했을 때, ‘광범위한 프레임워크 지원’과 ‘자동화된 코드 생성(Generator), UI 도구(Nx Console)’, ‘정교한 의존성 그래프 분석’이 Nx의 강력한 장점입니다.
• 도입 전에는 조직 내 코드베이스 규모, 팀별 협업 방식, DevOps 파이프라인 요구사항을 면밀히 따져봐야 하며, 파일럿 프로젝트를 통해 설정 복잡도를 확인하고 적용 범위를 결정하는 것이 좋습니다.
